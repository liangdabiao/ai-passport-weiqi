# 围棋闯关 —— 应用档案

本仓库家族的第四个应用，从 `qiaopi-quiz` 派生、保留完整 git 历史。内容源是网页游戏
《围棋闯关》，后者抽取自 online-go.com 的 LearningHub 教程（AGPL-3.0）。

## 内容模型与管线

网页版把 3564 关放在八个章节的 TypeScript 数据里。设备版沿用章节阶梯，只携带精选子集：

| 决策 | 取值 | 理由 |
| --- | --- | --- |
| 携带关卡 | 154 / 3564（解谜 119 / 选择 32 / 终局 3） | 全通关约八小时；等距抽样保住每章原教学顺序 |
| 棋盘尺寸 | 恒为 9x9 | 网页版 80% 关卡在 19x19 上；按「棋子+正解+标记」包围盒，**94%（2696/2860）装得进 9x9**。统一棋盘 = 一套渲染器、一套版式算术 |
| AI 对弈 | 不做 | 网页终局打 DeepSeek API；离线设备没有大模型，19x19 上的贪心 bot 也算不上「对弈」 |
| 背景音乐 | 不要（2.8MB） | 用户拍板：音效走合成，音频预算为零 |
| 语言 | 仅中文 | 屏面与 603 码点的字库预算都只够一种 |

管线在 `tools/weiqi/`：

1. `extract_levels.mjs`（node）用 esbuild **直接求值**网页版的章节 TS —— 上一应用确立的
   教训照用：正解路径是数据，绝不能用正则刮。它还处理了源数据里的两种坐标方言
   （goban 二字码 `cp` 与跳过 i 列的人类坐标 `b3`）。
2. 对每个候选关卡：算「棋子+正解+标记」的包围盒，在原棋盘上滑动 9x9 窗口（居中优先），
   并在**裁剪后的棋盘上按完整规则重新校验每条正解路径**（气 / 提子 / 禁自杀 / 简单劫）。
   裁剪可能切断棋块改变气的数量 —— 这样的关卡被舍弃，窗口搜索再救回大多数。
3. 通过的关卡写进 `levels.txt` —— 唯一事实源，人类可读的 `key: value` 区块。
   下游不许发明数据。
4. `content.py` 重解析并重校验（与抽取器同一套规则的两份实现），
   `gen_content.py` 投影成 `main/wq_content.c/h`，
   `gen_font.py` 把字符清单与界面字符串并成三档字库。

值得留意的实测数字：选中的 154 关只用 603 个码点（汉字 361）—— 家族里最小的一份字库；
正解路径平均 2.5 手（入选集中最长 9 手）；最大开局 43 颗子。

## 三键上的二维光标

最难的一道界面题：棋盘是网格，设备只有上/下/确定。全应用统一的语义：

- **上/下短按**：光标移一行（视觉上的上下）。
- **上/下长按**：移一列（左右）。BSP 对所有键都报长按；`main.c` 负责映射，
  `main/wq_session.c` 只在作答阶段消费它。
- **确定**：落子（或确认选项 / 移除死子 / 终局确认）。
- **确定长按**：逐层后退：作答 → 题面 → 关卡列表。

光标到边就停、不绕圈 —— 绕圈会让「我到底在第几行」失去参照。非法落点（占位/自杀/
劫回提）直接无视、不记错，与网页版一致。进关时光标初始落在第一个字母标记点上
（题面说的「下在 A 点」），没有标记就落在棋盘中心。

## 与网页版的刻意差异

- **走错即复位**并记一次错误 —— 网页版 bump 一个 React key 重建棋面；设备版从初始
  局面重摆。判题本身完全一致：每一手都必须延续某条脚本化正解路径。
- **没有对手 AI**：选择题与终局用不着；解谜题的对手应手就写在正解路径里
  （设备按「第一条仍匹配的路径」落应手，与网页 move tree 的分支序语义相同）。
- **仅中文**，深蓝金配色直接取自网页 CSS（`#1a1d2e` / `#f5c451`），
  棋盘是传统木色、由控件绘制而非贴图。

## 验证记录

`tools/validate.sh` 在家族共用的门禁之上加跑：

- `test_wq_engine` —— 规则单元用例（提子/自杀/反提/简单劫）+ **全量 134 条正解路径、
  280 手**在 C 引擎下逐手重放；
- `test_wq_session` —— **把 154 关全部真打通**，外加走错与答错的扣星用例；
- `test_wq_content` —— 生成表的每行都在声明边界内；
- `test_wq_wrap` —— 每段题面与题干在 13 字/行的真实预算下都折得进缓冲；
- `test_wq_progress` —— 星级打包、解锁链、校验和拒绝；
- `gen_content.py --check` / `gen_font.py --check` —— 生成表与字库不许和
  `levels.txt` 或界面文案脱节。

真机结果产生后记录在此。
